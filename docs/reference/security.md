## English

### 1. Overview
Defense in depth across the edge and the app: the ALB is reachable only through CloudFront (prefix-list SG + `X-Origin-Verify` header), the only paid endpoint (AI) is rate-limited on an unforgeable key, and the one place that fetches client-supplied URLs (`news.fetch_article_content`) carries SSRF, size and regex-DoS guards. Error bodies never leak internals.

### 2. Components
| Component | Path | Purpose |
|---|---|---|
| Origin verification | `infra/stacks/stock_monitoring_stack.py` (§3, §8, §9) | CloudFront injects `X-Origin-Verify` (Secrets Manager value); the ALB listener defaults to 403 and forwards only on a header match — direct ALB calls are blocked |
| ALB security group | `infra/stacks/stock_monitoring_stack.py` (§7) | Single ingress rule: CloudFront origin-facing prefix list (`pl-22a6434b`) on port 80; `open=False` keeps CDK from adding `0.0.0.0/0` |
| AI rate limiting | `backend/app/api/ai.py`, `backend/app/api/ratelimit.py` | 3 req/min/IP (sliding window) keyed on `CloudFront-Viewer-Address` + global concurrency 2; the limit precedes the cache so even cache hits spend budget |
| SSRF guard | `backend/app/services/news.py` | Client URLs only via http/https, private/link-local IPs blocked per resolved address, redirects capped at 3 and re-checked |
| Response size cap | `backend/app/services/news.py` | 256 KB (`MAX_ARTICLE_SIZE`) applied to declared content-length AND streamed bytes; no compression requested (decompression-bomb defense) |
| Bounded regexes | `backend/app/services/news.py` | Every tag-scanning class is `[^<>]{0,1000}` (`MAX_TAG_SCAN`); measured 39–136 s quadratic cases dropped to ≤0.03 s at 262 KB |
| Safe XML parsing | `backend/app/services/news.py`, `backend/requirements.txt` | `defusedxml` for third-party RSS — entity-expansion DoS and XXE blocked |
| Fixed error bodies | `backend/app/api/ai.py` | Clients only ever see `rate_limited` / `ai_unavailable` / `ai_failed` / `article_unavailable`; exception text (accounts, ARNs, model ids) goes to server logs only |
| Least-privilege IAM | `infra/stacks/stock_monitoring_stack.py` (§5) | Task role: DynamoDB actions scoped to the table ARN; `bedrock:InvokeModel` only |
| Input caps | `backend/app/api/ai.py`, `backend/app/models.py` | `MAX_URL_LEN` 2048 / `MAX_TITLE_LEN` 512 / `MAX_QUESTION_LEN` 200 — client input reaches prompts and cache keys, so its length is bounded; the question is also normalised (control characters dropped) and hashed before it enters a key |

### 3. Key Decisions
- **Rate-limit key = `CloudFront-Viewer-Address`, not `X-Forwarded-For`**: the first XFF entry is client-writable — rotating it evades any limit (demonstrated live 2026-08-02, hence the ruling). The viewer-address header is generated by CloudFront from the TCP connection and overwrites any viewer-supplied copy; it reaches the origin only because the CDK origin request policy whitelists it. Fallback (XFF → socket) applies only off CloudFront (local dev).
- **Cost defense is triple-layered**: per-IP rate limit → result cache → global concurrency semaphore. No single control is load-bearing.
- **Prompt injection via the free-form question is contained, not prevented**: the question is fenced in `<question>` delimiters with explicit instructions (ignore embedded directives, stay within the provided data, no trade orders), normalised and capped at 200 characters. The model can still be steered within that box, but the output is Korean markdown rendered by react-markdown without raw HTML, the prompt carries only public market facts (no secrets, no tools), and the cost is bounded by the per-IP limit — so the worst case is a poor answer, not exfiltration or spend.
- **The regex bounds are load-bearing**: `[^<>]{0,1000}` excludes `<` (each candidate's scan ends at the next tag) *and* caps the scan length — both parts matter; `(.*?)</p>`-style lazy scans measured quadratic (136 s at 262 KB).
- **SSRF checks re-run per redirect hop** (up to 3): every hop's scheme and resolved IP is validated, not just the first URL.
- **`viewer_ip` splits on the *last* colon** so IPv6 addresses (which contain colons) survive port stripping; bracketed forms accepted.
- **Origin secret rotation = stack redeploy** (`unsafe_unwrap` is required by listener conditions / CloudFront custom headers — see [iac.md](iac.md)).

## 한국어

### 1. 개요
엣지와 앱을 관통하는 다층 방어: ALB는 CloudFront를 통해서만 접근 가능(prefix-list SG + `X-Origin-Verify` 헤더), 유일한 유료 엔드포인트(AI)는 위조 불가한 키로 레이트리밋되며, 클라이언트가 준 URL을 조회하는 유일한 지점(`news.fetch_article_content`)에는 SSRF·크기·regex DoS 가드가 있다. 오류 본문은 내부 정보를 절대 노출하지 않는다.

### 3. 주요 결정
- **레이트리밋 키 = `CloudFront-Viewer-Address`, `X-Forwarded-For` 아님**: XFF 첫 항목은 클라이언트가 채울 수 있어 요청마다 바꾸면 한도를 무한 우회한다 (2026-08-02 라이브 실증 → 사용자 결정). viewer-address 헤더는 CloudFront가 TCP 연결에서 직접 생성하며 뷰어가 보낸 동명 헤더를 덮어쓴다. CDK origin request policy가 화이트리스트해야만 오리진에 도달한다. 폴백(XFF → 소켓)은 CloudFront를 거치지 않는 로컬 개발에서만.
- **비용 방어는 3중**: IP별 레이트리밋 → 결과 캐시 → 전역 동시 실행 세마포어. 단일 컨트롤에 의존하지 않는다.
- **자유 질의의 프롬프트 주입은 '봉쇄'가 아니라 '격리'다**: 질문은 `<question>` 구분자 안에 넣고 내부 지시 무시·데이터 범위 유지·매매 지시 금지를 명시하며, 정규화 후 200자로 자른다. 그 상자 안에서 모델이 흔들릴 수는 있지만, 출력은 react-markdown이 raw HTML 없이 렌더하는 한국어 마크다운이고, 프롬프트에는 공개 시장 사실만 있으며(비밀·도구 없음), 비용은 IP별 한도가 묶는다 — 최악은 '나쁜 답'이지 유출이나 과금 폭주가 아니다.
- **regex 상한이 load-bearing**: `[^<>]{0,1000}`은 `<` 제외(후보별 스캔이 다음 태그에서 종료)와 길이 상한 두 가지가 모두 필요하다. `(.*?)</p>` 류 게으른 스캔은 실측 O(n²) (262KB에서 136초).
- **SSRF 검사는 리다이렉트 홉마다 재실행** (최대 3회): 첫 URL만이 아니라 모든 홉의 스킴·해석된 IP를 검증.
- **`viewer_ip`는 마지막 콜론에서만 자른다** — IPv6 주소 자체가 콜론을 포함하므로. 대괄호 형태도 허용.
- **오리진 시크릿 로테이션 = 스택 재배포** (`unsafe_unwrap`은 리스너 조건/CloudFront 커스텀 헤더의 제약 — [iac.md](iac.md) 참조).
